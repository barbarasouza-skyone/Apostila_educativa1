↗️ 1. Integrações e Fluxos

✅ Desafio Prático: Conexões de APIs, Fluxos e Filtros com JSONata

Neste desafio, você fará a ponte entre os sistemas simulados no Playground e a plataforma Skyone Studio. Você vai configurar as autenticações, testar as chamadas e construir fluxos de integração para extrair dados específicos. Siga o passo a passo com muita atenção aos alertas:

Preparação e Geração de Token (Playground)

  • Acesse o Playground e faça o download dos arquivos .iac referentes aos sistemas de E-commerce e de WMS.
  • Crie 1 (um) Token de acesso e clique no botão "Usar para testes" para ativá-lo.
Alerta Crítico: Copie este token e salve em um bloco de notas imediatamente! Após clicar para testar, o token irá sumir da tela e você não conseguirá copiá-lo novamente.

Importação e Nomenclatura Segura (Studio)

  • Volte ao Skyone Studio e faça a importação dos arquivos .iac que você baixou.
REGRA DE OURO: Assim que o arquivo for importado, você deve obrigatoriamente alterar o nome do Módulo para o formato: [Nome do Sistema] + [Seu Nome]. Por que isso é importante? Se você deixar o nome padrão, o Studio vai bloquear a ação acusando que "o módulo já existe".

Configuração da Autenticação (Conta de Conexão)

  • Vá até a seção de autenticação e crie as Contas de Conexão para os sistemas.
  • Preencha todos os parâmetros obrigatórios exigidos pela API. Certifique-se de inserir corretamente o Host, a Porta e o Token.
  • Após preencher tudo, salve as alterações.

Validação da Conexão (Teste de Fogo)

  • Antes de criar a integração, precisamos ter certeza de que o Studio está conversando com a API.
  • Entre em qualquer Operação dentro do seu módulo recém-criado.
  • Navegue pelo fluxo da operação até chegar no "Passo 4".
  • Clique no botão "Testar". Se a requisição retornar sucesso, sua conexão está validada!

Construção da Integração e dos Fluxos

  • Crie 1 (uma) Integração no Studio.
  • Dentro desta integração, você deverá construir 2 (dois) fluxos separados:
    • Fluxo 1 (WMS): Configurado para buscar os dados de inventário (estoque).
    • Fluxo 2 (E-commerce): Configurado para buscar os dados de pedidos, extraindo especificamente os itens de cada pedido.

💡 O Toque Mágico: Durante a construção destes fluxos, utilize o JSONata para aplicar filtros na resposta da API, garantindo que o seu fluxo entregue apenas os dados exatos que precisamos, de forma limpa e estruturada.

↗️ 2. Configurações do Lakehouse

✅ Desafio Prático: Estruturação de Dados (Data Lake e Data Warehouse)

Antes de construirmos nossos dashboards e agentes, precisamos preparar o terreno onde as informações vão habitar.

Criação do Banco de Dados (Data Warehouse)

  • Acesse o Data Warehouse e crie um novo Banco de Dados.
  • Regra de Nomenclatura: O banco de dados deve ser criado obrigatoriamente com o seu próprio nome. Isso garante que seu ambiente seja isolado e fácil de identificar.

Organização dos Arquivos (Data Lake)

  • Acesse o Data Lake.
  • Na pasta raiz do sistema (identificada pelo caminho /), crie uma nova pasta, também levando o seu próprio nome.

Configuração do Consumidor de Dados (ODBC)

  • Navegue pelo menu: Data Management -> Engine -> ODBC.
  • Crie um novo Consumidor de Dados utilizando o seu nome. É através deste consumidor que a "Elisa" vai se conectar.

Execução das Queries (Arquitetura Medalhão)

  • Execute as queries em ordem para criar e popular as tabelas.
Atenção ao ajuste na camada GOLD: Ao rodar as queries da camada Gold, você não deve simplesmente copiar e colar. Será necessário fazer um ajuste na linha em destaque de cada query para apontar/adicionar corretamente os arquivos.

CREATE OR REPLACE TABLE silver_orders (
    id INTEGER PRIMARY KEY,
    order_id INTEGER,
    product_id INTEGER,
    product_sku VARCHAR, -- Extraído do objeto product
    product_name VARCHAR, -- Extraído do objeto product
    quantity INTEGER,
    unit_price DECIMAL(18,2),
    total_price DECIMAL(18,2),
    processed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO silver_orders (id, order_id, product_id, product_sku, product_name, quantity, unit_price, total_price)
SELECT
    id,
    order_id,
    product_id,
    json_extract_string(product, '$.sku'),
    json_extract_string(product, '$.name'),
    CAST(quantity AS INTEGER),
    CAST(unit_price AS DECIMAL(18,2)),
    CAST(total_price AS DECIMAL(18,2))
FROM bronze_orders
ON CONFLICT (id) DO UPDATE SET
    product_sku = EXCLUDED.product_sku,
    product_name = EXCLUDED.product_name,
    total_price = EXCLUDED.total_price;

SELECT * FROM silver_orders;

🟡 Camada GOLD [Ecommerce + WMS]

CREATE OR REPLACE TABLE gold_dwh_vendas_estoque AS
SELECT
    -- Dados do Pedido (Vindo da silver_orders)
    o.id AS item_pedido_id,
    o.order_id,
    o.product_sku AS sku,
    o.product_name AS nome_no_pedido,
    o.quantity AS quantidade_vendida,
    o.unit_price AS preco_unitario,
    o.total_price AS valor_total_item,
    i.category AS categoria_produto,
    i.stock_quantity AS estoque_atual_disponivel,
    (i.stock_quantity - o.quantity) AS estoque_projetado,
    now() AS data_analise
FROM silver_orders o
LEFT JOIN silver_inventory i ON o.product_sku = i.sku;

SELECT * FROM gold_dwh_vendas_estoque;

📝 Prompt: Agente de Gestão de Estoque Preditiva

# Assistente de Gestão de Estoque Preditiva
Olá! Eu sou o seu **Analista de IA para Supply Chain**. Minha função é monitorar o 'gold_dwh_estoque_vendas' em tempo real para evitar rupturas e otimizar seu inventário.

### O que eu posso fazer por você?
Consigo realizar análises complexas cruzando dados de vendas históricas com previsões de estoque. Meus principais comandos incluem:
* **Detecção de Ruptura:** Identifico quais SKUs estão com estoque projetado negativo ou crítico.
* **Cálculo de Reposição:** Sugiro a quantidade ideal de compra baseada na sua média de vendas recente.
* **Análise por SKU:** Forneço um raio-x completo de um produto específico.

### Formato de Resposta
Minhas respostas seguirão este padrão para facilitar sua decisão:
* **SKU / Produto:** Identificação clara.
* **Status:** (Crítico / Alerta / Saudável).
* **Estoque Atual vs. Projetado:** Números reais do DWH.
* **Ação Sugerida:** Quantidade exata para compra.
* **Justificativa:** O "porquê" analítico por trás do número.

import pandas as pd
import json
import logging
from typing import Dict, Any, List
from sqlalchemy import create_engine, text
from sqlalchemy.orm import sessionmaker

logger = logging.getLogger(__name__)

def execute_query(query: str, params: Dict[str, Any] = None) -> dict[str, Any]:
    # Executa queries SQL no DWH via SQLAlchemy 2.0.
    database = ""
    user = ""
    password = ""
    host = ""
    
    logger.info("BI Analyst: Executing query on gold_dwh_vendas_estoque")
    conn_string = f"postgresql+psycopg2://{user}:{password}@{host}:9000/{database}"
    
    engine = create_engine(conn_string, pool_pre_ping=True)
    Session = sessionmaker(bind=engine)
    session = Session()
    try:
        sql_text = text(query.replace("`", ""))
        if query.strip().upper().startswith(("WITH", "SELECT")):
            df = pd.read_sql(sql_text, session.bind, params=params)
            result = df.to_dict("records")
            return {"result": json.loads(json.dumps(result, default=str))}
        else:
            session.execute(sql_text, params)
            session.commit()
            return {"result": "Operação de escrita concluída."}
    except Exception as e:
        session.rollback()
        logger.error(f"DWH Query Error: {str(e)}")
        return {"error": str(e)}
    finally:
        session.close()

def get_low_stock_alerts() -> Dict[str, Any]:
    query = """
    SELECT
        sku, nome_no_pedido, estoque_atual_disponivel, estoque_projetado,
        CASE
            WHEN estoque_projetado <= 0 THEN 'CRÍTICO: Ruptura Iminente'
            WHEN estoque_projetado <= 5 THEN 'ALERTA: Estoque Baixo'
            ELSE 'SAUDÁVEL'
        END as nivel_criticidade
    FROM gold_dwh_vendas_estoque
    WHERE estoque_projetado <= 5
    ORDER BY estoque_projetado ASC
    """
    return execute_query(query)

def suggest_replenishment(sku: str = None) -> Dict[str, Any]:
    where_clause = "WHERE sku = :sku" if sku else "WHERE estoque_projetado <= 5"
    query = f"""
    WITH metrics AS (
        SELECT
            sku, nome_no_pedido, estoque_atual_disponivel, estoque_projetado,
            AVG(quantidade_vendida) OVER(PARTITION BY sku) as media_vendas_item,
            SUM(quantidade_vendida) OVER(PARTITION BY sku) as total_vendido
        FROM gold_dwh_vendas_estoque
        {where_clause}
    )
    SELECT
        sku, nome_no_pedido, estoque_atual_disponivel, estoque_projetado,
        CEIL(media_vendas_item * 1.5) as sugestao_compra,
        'Baseado em 1.5x a média de vendas recente para garantir cobertura.' as justificativa
    FROM metrics
    LIMIT 10
    """
    params = {"sku": sku} if sku else None
    return execute_query(query, params)
